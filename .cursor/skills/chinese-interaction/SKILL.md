# 交互语言：一律使用简体中文

## 适用范围

本规则覆盖 agent 窗口 / chat 窗口中**由 AI 生成的全部文字**，不限于最终答复。具体包括：

- **状态与进度叙述**，例如「正在重新编译 x64 Release…」「已修复 3 处问题，正在验证…」
- 工具调用前后的说明文字（preamble），例如「先读取 `src/iso.c` 的相关片段」
- 分析、推理、排查过程的文字说明
- 待办清单（todo）标题与条目
- 计划、步骤拆解、核对表
- 提问、澄清请求、供选择的选项
- 审核/评审发现的问题及解释
- 总结与结论

**判断标准**：凡是会显示在窗口里给人看的自然语言文字，都用中文。即使在两次工具调用之间的短句、或仅一句过渡性状态说明，也必须用中文，不要中英夹杂。

即使提问是英文、上下文含英文材料，也用中文作答。

## 必须使用简体中文的内容

以下内容**一律使用简体中文**：

- **commit message** —— 标题与正文都用中文（本仓库是 fork，不遵循上游 Rufus 的英文约定）
- **changelog 条目** —— 新增的变更说明条目
- **代码注释** —— 新增或修改所涉及的注释
- 新增的说明文档

## 存量代码不要求改动

**仅约束今后新增和修改的内容**。仓库中既有的英文注释、英文文档、英文历史提交记录**保持原样，不要为了「统一成中文」而翻译或重写**。

意味着：

- 修改某个函数时，只为**本次改动新增或调整的注释**写中文；该文件里其它已有英文注释不动
- 不要批量翻译存量英文注释，也不要把它们当作待办事项
- 就近的已有英文注释可以保持英文，与新增中文注释共存是允许的

## 中文注释的编码要求

源码文件必须保存为 **UTF-8**。项目的 `rufus.vcxproj` 已配置 `/utf-8` 编译选项，因此中文注释可正常编译。**不要**把源码文件保存为 ANSI/GBK，否则会出现乱码或 C4819 警告。

修改源码时必须使用能保持 UTF-8 编码的工具，**不要**用会按系统代码页转码的读写方式（如 PowerShell 的 `Get-Content` + `Set-Content` 默认组合），否则会破坏文件中的既有多字节字符。

## 保持原文、不要翻译的内容

以下属于代码、命令或机器可读内容，**必须保持原样**（翻译会导致无法复现问题或破坏文件）：

- 源代码、标识符、字符串字面量（注释除外，见上）
- 文件名与路径
- 编译命令与参数（`MSBuild rufus.sln /p:Configuration=Release`）、`vcvars`、CMake 等
- `git` 命令及其原始输出
- `res/loc/rufus.loc` 中的 en-US 词条文本
- 日志文本与错误码（`ERROR_CANCELLED`、`MSG_375`、`C4819`）
- 工具原始输出

引用报错或工具输出时**保留原文**，随后用中文解释其含义。专有名词保留英文原词，例如 `oscdimg`、`El Torito`、`UDF`、`Joliet`、`unattend.xml`、`boot.wim`。

## 说明

VS Code 界面自身的固定控件文字（如按钮、菜单、面板标题）由编辑器提供，不受本规则控制。本规则约束的是 AI 在本会话中生成的所有文字。
